# Vector60 → Vector75 技术债清单

状态：`planning_only`

本文只定义 Vector60 后续验证与实验路线，不表示 Vector60 已通过，也不表示
Vector75 已实现。Vector75 是 KORYAO 自有基准的候选阶段名，不与
Vectorizer.AI 的官方性能、实现或结果作等价声明。

## 当前证据缺口

以下项目在进入 Vector75 实验前必须保持为 `unverified`，不能由单元测试或
预览图替代：

- 40 张 Vector60 验收图尚未提供，四类各 10 张的正式结果、前后对比图和
  原分辨率最终 SVG 渲染指标均未产生。
- 4x 检查图可以由本地 runner 生成，但尚未完成人工白缝复核。
- Exact 的 `pixel_match=true`、`different_pixel_count=0`、
  `maximum_channel_difference=0` 尚需在每个候选发布检查点持续门控。
- Node.js 与 SVGO 未打入 Python sidecar；当前不能把安装包描述为包含完整
  SVGO 运行时。
- Windows 内部测试 workflow 尚未执行。
- 干净 Windows 环境安装、Microsoft Defender 扫描、SmartScreen 行为和
  安装包签名均未验证。

## 优先级与量化验收

表中“验收 / 实验设计”是下一阶段的退出条件，不是当前已通过的结果。

| 优先级 | 技术债 / 方向 | 主要风险 | 量化验收 / 实验设计 | 依赖与能力边界 |
| --- | --- | --- | --- | --- |
| P0 | 补齐 40 图 Vector60 正式验收证据 | 在没有素材和最终渲染证据时误报质量 | 仅使用显式本地 manifest；四类各 10 张；每张候选均由最终 SVG 按原分辨率实际渲染后评分；成功数、Edge Dice、normalized MAE、锚点、子路径、体积与耗时均进入匿名汇总；先完整通过 Vector60 硬门，再建立 Vector75 基线 | 素材、最终 SVG、渲染图和对比图只留在 Git 忽略目录；不记录路径、文件名、内容或账号信息 |
| P0 | 完成 4x 白缝人工复核 | 自动指标漏掉细缝，或把自动生成的检查图误记为已复核 | 40 张均生成 4x 检查图；由两名复核者独立标注“明显白缝 / 无明显白缝”，分歧项复核；至少 32 张无明显白缝才满足现有 Vector60 门槛；同时记录类别分布和复核一致率，目标 Cohen's κ ≥ 0.80 | 人工记录只使用匿名 case ID；不把素材和检查图提交到仓库 |
| P0 | Exact 三值持续回归门控 | Artisan 优化或公共入口变动破坏 Exact | 每个候选发布检查点运行固定的公开测试样例；任一项不满足 `true / 0 / 0` 立即阻断；对新增的透明、半透明、调色板与 RGBA 边界样例各增加至少 3 个确定性用例 | 不改 Exact 默认行为；不调用 Illustrator Image Trace；不允许自动降级为近似描摹 |
| P0 | 明确 Node.js / SVGO sidecar 交付策略 | 干净机器缺少 Node.js 时清理步骤不可用，安全验证与开发机不一致 | 在“随安装包固定打入 Node.js + SVGO”与“独立受控 runtime”两案中各制作可复现原型；在无全局 Node.js 的干净 Windows VM 上运行 20 次，要求 20/20 完成 SVGO 安全清理、版本与哈希可追溯、离线运行且无网络访问；未达标前构建元数据继续声明 `bundled=false` | SVGO 固定版本；记录许可证、版本、提交/制品哈希和用途；不得下载或复制完整第三方仓库 |
| P0 | 执行 Windows 内部 workflow 与安装包验收 | CI 绿色但真实 sidecar、安装器或桌面启动失败 | 手动触发内部 workflow；记录 workflow 结论与制品哈希；随后在两台干净 Windows VM 各执行安装、启动、四模式 smoke test、卸载，要求全部成功且不覆盖输入图 | 只验证 KORYAO 矢量化与打包边界；不扩大 Adobe、macOS、ComfyUI、AutoCAD、Blender 或 CapCut 能力声明 |
| P0 | Defender、SmartScreen 与签名验证 | 安装包被拦截、来源提示不清或签名链不可验证 | 对最终候选执行 Defender 离线/云扫描并保留脱敏结论；在默认 SmartScreen 策略下记录首次启动行为；使用组织批准的代码签名后验证签名、时间戳与 SHA-256；两台干净 VM 均通过才可把相应项标记为 verified | 证书、账号、签名密钥和扫描原始日志不得进入仓库；签名需要人工授权 |
| P1 | 场景分类置信度与保守回退校准 | 错误场景预设导致插画退化，照片被伪报高质量 | 另建不与 40 图验收集重叠的至少 100 张匿名校准集；报告五类混淆矩阵与置信度可靠性；`unsupported_photo` 召回率目标 ≥ 0.95；低置信度样例 100% 回退现有 smart 或 Artisan baseline | 仍只公开 exact、smart、lightweight、artisan 四模式；不得新增第五模式 |
| P1 | 候选矩阵按场景做消融 | 参数组合增加耗时却未改善 Pareto 前沿 | 每场景比较 4、8、12 候选，所有候选均实际渲染；在独立验证集上，仅当 Edge Dice 中位数提升 ≥ 0.01 或 normalized MAE 中位数下降 ≥ 0.01，且 p95 耗时不增加超过 30% 时接受新组合；总候选始终 ≤ 12 | 生产候选只使用已批准的 VTracer、skia-pathops、svgpathtools 与 SVGO；每次只改变一个参数族 |
| P1 | Alpha 感知边缘与细线评分 | RGB 指标掩盖透明边缘或细线丢失 | 建立至少 20 张透明/半透明与 20 张细线合成夹具；分别报告 alpha MAE、Edge Dice 和细线召回率；新评分器必须使细线召回率提升 ≥ 3 个百分点，同时总体 normalized MAE 不恶化超过 0.005 | 合成夹具须可由代码生成且不含客户素材；preview 不能作为正式证据 |
| P1 | 缝隙修复拓扑与色差校准 | union、吸附或重叠改变孔洞、父子关系和颜色边界 | 生成至少 50 组含孔洞、嵌套、相切与近色边界的确定性夹具；要求拓扑保持率 100%，修复后指标不下降；继续限制顶点吸附 ≤ 0.8 px、安全重叠 ≤ 0.4 px，并对 Delta-E 阈值做盲测选择 | 只允许 pathops 的 union/intersection/difference/xor；禁止全图无条件膨胀；失败保留 `artisan_baseline.svg` |
| P1 | 规则图元拟合覆盖与拒绝策略 | 错把手绘轮廓替换成规则图形 | 对直线、矩形、圆角矩形、圆、椭圆、规则多边形各准备至少 20 个正例和 20 个近似反例；正例接受率目标 ≥ 90%，反例误替换率 ≤ 1%；轮廓、面积、拓扑与最终渲染四门全部通过才替换 | 使用 svgpathtools 分析与最终渲染复核；不得凭路径参数或预览单独接受 |
| P1 | 失败注入与 baseline 可恢复性 | 单候选异常造成无输出或发布半成品 | 对分类、预处理、VTracer、几何处理、渲染、评分、SVGO 和安全验证逐阶段注入异常；每阶段至少 3 个用例；要求 100% 返回已验证的 `artisan_baseline.svg`，且报告不泄露异常中的路径或素材内容 | 不放宽安全验证；不覆盖输入；失败输出只写入受控忽略目录 |
| P2 | 曲线连续性与锚点 Pareto 优化 | 只减少锚点却引入折点、细节丢失或假简化 | 在通过 Vector60 的最终 SVG 上比较基线与候选：G1 不连续点减少 ≥ 20%，锚点中位数再减少 ≥ 10%，同时 Edge Dice 中位数下降不超过 0.005、normalized MAE 增加不超过 0.003；未同时满足则拒绝 | VTracer 仍是初始候选；不宣称“手绘”或设计师语义分层 |
| P2 | 评分器跨类别稳健性 | 总体中位数掩盖某一类别退化 | 除总体门槛外，对四类分别 bootstrap 10,000 次报告 95% 置信区间；任何类别 Edge Dice 中位数下降 > 0.01 或 MAE 上升 > 0.01 时不得升级默认参数 | 报告仅含匿名统计；不得输出素材内容或可反推来源的元数据 |
| P2 | 性能、缓存与确定性预算 | 候选增多导致等待时间不可控或结果漂移 | 固定环境对 40 图各运行 3 次；输出 SVG SHA-256 必须 3/3 一致；记录 p50/p95 耗时与峰值内存；Vector75 候选的 p95 耗时不超过 Vector60 基线 1.5 倍，峰值内存不超过 2 GB | 缓存键只用内容哈希和公开参数；报告不得保存源路径；不依赖网络 |
| P2 | 第三方依赖与供应链复核 | 许可证遗漏、版本漂移或生产依赖扩大 | 每个 release candidate 自动核对 VTracer、skia-pathops、svgpathtools、SVGO 的许可证、精确版本、提交/制品哈希和用途；缺一项即阻断；生成 SBOM 并在无网络环境重建一次 | diffvg 与 LIVE 仅允许离线、只读研究；不得进入生产依赖、安装包或默认工作流 |

## Vector75 候选门槛的制定方式

Vector75 的数值门槛必须在 Vector60 全量证据完成后，用预注册实验确定，不得先
命名结果再选择有利指标：

1. 冻结 40 张 Vector60 验收集，仅用于回归；另建不重叠的校准集和盲测集。
2. 在实验前登记主要指标、允许退化量、耗时预算和统计方法。
3. 所有候选继续经过最终 SVG 原分辨率实际渲染、安全验证和 Pareto 选优。
4. 只有盲测集达到预注册门槛、四模式回归保持绿色、Exact 三值不变、失败回退
   100% 通过，才讨论将实验默认值升级。
5. 失败、跳过和未验证项分别报告；不得把缺失证据计为通过。

## 明确不进入 Vector75 生产范围

- diffvg 与 LIVE 保持 research-only；只能做离线消融，不进入今日或下一阶段
  生产依赖。
- 不增加第五种公开矢量化模式，不改变 Exact、Smart、Lightweight 的默认输出。
- 不使用 Illustrator Image Trace，不嵌入位图、Base64、外链或脚本。
- 不扩大 macOS、Adobe、ComfyUI、AutoCAD、Blender、CapCut 的现有能力边界。
- 不复制完整第三方仓库，不上传用户路径、Token、Cookie、账号状态、素材或
  临时输出。
